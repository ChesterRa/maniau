## 1. 一言で

**まだ選べるうちに、間に合わなくなる所を知らせ、次の一手を示して、家族の誰かが引き受けるまで追う。**

カレンダーに書けるのは「その日」だけである。まにあうが扱うのは、その日に間に合わせるために「いつまでに・誰が・何を決めるか」と、予定が変わった時に「何が要らなくなり、何が残るか」である。

まにあうは、お知らせを、家族それぞれの一週間の「いつ・どこで・誰が・何を」に置く。家の場所、職場、通勤、お迎えの担当を知っているので、「帰り道の駅の店で、閉まる前に買える」まで示せる。場所と暮らしを知らないままでは、一般的な助言にしかならない。

## 2. 例：学習発表会のお知らせ一枚から

デモと試験は、架空の家族で行う（`data/demo/`）。人・学校・学童の名前と決まり、お知らせの文は架空である。駅・線路・店・営業時間・暦は実在の物を使う。地域は豊洲の辺り（東京都江東区）とする（2026-11-02 決めた。作り手の家に近ければ替える）。日付は近い未来にし、地図のデータを実際に調べられるようにする。

（2026-11-02 夕方に改めた。前の版の例は5月の運動会だった。架空の場所と日付で組むと、細部が互いに合わなくなる、という作り手の指摘による。前の版の日付を27週後へ移すと曜日がそのまま合い、間に祝日も無いので、確かめた決め時の筋はそのまま使える）

- 子：小学1年生。放課後は学童に通う。
- 親A・親B：どちらも平日は電車で出社する。学童のお迎えは、月・水・金が親A、火・木が親B。
- 祖母：電車で40分。頼むなら3日前までに知りたい。

11/25(水)、学校からお知らせが届く（年は2026年。曜日と祝日は確かめてある。11/23は祝日で、この期間より前）。

> 12月5日(土)に学習発表会を行います。1年生の発表は9時20分からです。衣装として、白い長袖シャツを用意してください。5日(土)に行った場合、12月7日(月)は振替休業日です。感染症の流行状況により延期する場合は、12月8日(火)に行います。延期した場合、7日(月)は通常授業とします。

（延期の条件は、最初のお知らせに書いてある形にする（2026-11-02 決めた）。まにあうは日程だけを扱い、健康の助言はしない）

カレンダーの道具なら、12/5に「学習発表会」と書いて終わる。まにあうは、次を返す。

1. **12/7(月)は学校が休みで、二人とも仕事がある。** 子の居場所を決める必要がある。案は三つあり、それぞれ決め時が違う。
   - 学童の一日利用（休まずに済む）：利用届を、11/30(月)のお迎えの時までに出す（学童の決まり。家族が登録した物）。当日はお弁当が要る。
   - 有休：12/2(水)までに申請する（勤務先の決まり：3営業日前）。
   - 祖母に頼む：12/4(金)までに頼む。
   - 画面には「休まず、祖母にも頼まずに済む方法（学童）は、11/30(月)のお迎えまで。それを過ぎると、祖母に頼むか、休むことになる」と出す。
2. **白い長袖シャツが家にあるかは、分からない。** 答えで「やる事」が変わるので、これは聞く。無ければ、二人のふだんの週（帰り道の駅、お迎えの担当）と店の営業時間から、買える時と場所を示す（例：お迎えの無い日の親Aの帰り道、駅の近くの店で閉店前に）。答えで何も変わらない事は、聞かない。
3. **誰が引き受けるか。** 振替休業日は家で過ごさせたいので、家族が祖母に頼むと決め、親Bが頼む役を引き受けたとする。案を選ぶのは家族で、まにあうは代償と決め時を示す。
   - 祖母の返事が来るまでは「返事待ち」とし、確定とは言わない。
   - 返事がないまま11/29(日)の夜になったら、学童の決め時（翌日のお迎え）が近いことを、頼んだ親Bにだけ知らせる。学童の届けを予備に出しておく案も示す（要らなくなれば取り消せる）。
   - 月曜のお迎えは親Aなので、届けの提出は親Aに頼む案を出す。親Aが「引き受ける」を押すまでは、決まっていない事として扱う。

12/4(金)の夕方、学校から「流行のため、学習発表会は12月8日(火)に行います」と届く。

4. まにあうは、最初のお知らせの条件から、次を導く。
   - 12/7は通常授業になった。12/7の子の居場所の手配は要らない。頼んだ後の物は、取り消しの連絡に変える：祖母へ「来なくてよくなった」（親Bに）、学童へ届けの取り消し（出していれば、親Aに）。学童の日のお弁当の準備も外す。済んだ作業があれば、記録は残す。
   - 衣装（白い長袖シャツ）は、12/8にも要る。そのまま残す。
   - 発表会が平日（12/8(火)）になった。見に行くかは任意である。行くなら、有休の申請期限（3営業日前の12/3）は過ぎているので、時間休になる（前日までに申請）。

この一連の流れを、元の文に戻れる形で、二人それぞれの画面に出す。

## 3. 何が「AIを包んだだけ」ではないか

おたよりの読み取り、家族への割り当て、衝突の指摘は、すでに多くの製品がある（[../research/03-prior-systems.md](../research/03-prior-systems.md)）。まにあうは、その先の六つを仕組みとして持つ。

| 層 | 中身 | 素のチャットで起きると見込むこと（§7で測る） |
|---|---|---|
| 出典と条件の付いた事実 | 何が、どの文から、どの条件の時に要るか（「5日に行った場合は、7日が振替休業日」） | 条件を落とし、全部を一律に「要る」とする |
| 前提が崩れた準備の取り消し | 変更を受けて、依存を辿って要らない物を外し、要る物は残す。人に頼んだ後なら「取り消しの連絡」に変える | 全体を作り直し、頼んだ相手への連絡を忘れる |
| 選択肢の決め時 | 各案を実行するための最後の決め時を、申込の締切・返事にかかる時間・営業時間・勤務から逆算する | 行事の日だけを見て、手遅れの案を勧める |
| 聞くべき事だけ聞く | 答えで決め方が変わる事だけを、決め時より前に聞く | 全部を確かめさせるか、確かめずに決めつける |
| 引き受けまで追う | 提案・引き受け・条件待ち・確定・済みを分け、決め時に間に合うように追う | 返事待ちを確定と扱う。追うのは結局、人になる |
| 暮らしの中に置く | 家の場所・職場・通勤・お迎えの担当・店の営業時間から、いつ・どこで・誰がを決める（例：お迎えの無い日の帰り道、駅の近くの店で閉店前に） | 場所と暮らしを知らず、「週末に買いましょう」のような一般的な助言になる |

計算で保証する部分（日付、適用、取り消し、決め時、配置、検証）はコードが受け持ち、Claude は読み取り・書かれていない準備の推定・変更の解釈・説明を受け持つ（[../design/01-model.md](../design/01-model.md) §1）。

要素の手法は、どれも既知である。この六つの軸で競合を確かめるのは、これからである（[../research/03-prior-systems.md](../research/03-prior-systems.md) §6）。確かめた後も、言えるのは「確かめた範囲で、この組み合わせを家庭の段取りに当てた例は見当たらない」までとし、差は比べた結果で示す（§7）。

## 4. 誰の、何のためか

- 小学生・保育園児のいる、共働きやひとり親の家庭。平日の日中に親が要る予定と、急な変更で、段取りが崩れる家庭である（[../research/00-synthesis.md](../research/00-synthesis.md) §1）。
- 作り手は、日本で子どもを育てている親である。作り手の家の実際のおたよりと予定で、毎日使って確かめる。実際の材料は、リポジトリの外に置く（[../dev/repository.md](../dev/repository.md)）。
- 減らしたいのは、段取りを受け持つ人が頭の中でしている、次の仕事である。
  - 届いたおたよりから、要る事と期限を拾う。
  - どの手がいつまで取れるかを考える。
  - 相手に頼み、返事を待ち、追いかける。
  - 予定が変わったら、何が要らなくなったかを考え直し、頼んだ相手に伝える。
- 確かめる問い：**一回の操作の後、段取りを受け持つ人は、もう一度追いかける必要があるか。** 入力と確認にかかる手間も、得る物と一緒に数える。

## 6. 判断の関門

### G1（11/3 14:00）

二つの門を分けて判断する。

- **製品の門**：作り手が、自分の家の最近の出来事2〜3件（例：振替休業日、平日の行事、急な変更）を、§2の流れ（紙や試作でよい）に当てはめる。
  - 見ること：その時に本当に決めるべき事と期限が出るか。相手に任せられる形か。自分が追いかける回数が減るか。入力と確認の手間が見合うか。
  - 決めること：このまま続ける／画面と流れを直す／扱う出来事の種類を変える。
- **技術の門**：境界の場面3〜4個（決め時の経過、取り消し、返事待ち、答えで変わる問い）で、強い比較相手（§7）を試す。
  - 比較相手がほとんど正しく扱える：求解は小さく保ち、状態と追跡（事象、引き受け、時計）に力を寄せる。
  - 崩れる：その崩れ方を、求解と検証で防ぐ所として前に出す。
  - どちらでも製品は続ける。この門が決めるのは、求解をどこまで深くするかである。

### G2（11/5）

評価の結果と、作り手の実際の使用で、残す機能と動画の筋を確定する。

## 7. 確かめ方

### 7.1 境界の場面（6〜12個）

小さく、正解を人が確かめられる場面を作る。

1. 決め時の経過：締切を過ぎた後、その案を勧めないか。
2. 答えで変わる問い：答えで決め方が変わる時だけ聞くか。変わらない時に聞かないか。
3. 引き受けの後の辞退：辞退の後、何を決め直すかが正しいか。
4. 返事が来ない：返事待ちの案を、確定と扱わないか。予備の案の決め時の前に知らせるか。
5. 要件の取り消し：変更で要らなくなった準備を外し、要る物を残すか。頼んだ相手への連絡を作るか。
6. 判断できない時：計算が時間内に終わらない時、そう示すか。
7. 祝日をまたぐ営業日、勤務の後に閉まる店、同じ晩に重なる作業。

### 7.2 比べる相手

- **強いClaude**：同じモデルに、同じ家族の情報、おたより、今の時刻、それまでの事象を渡す。質問を許し、正解を知っていて質問に答える係を置く。日付の計算の道具も持たせる。プロンプトは3通り以上試し、最良を使う。
- 必要なら、本作から一つの部品を外した物（例：取り消しの依存を持たず、毎回作り直す）。
- 入力は二通りで測る：元の文から通しで／正解の事実から。読み取りの誤りと、計画の誤りを分ける。
- 指標：外し漏れ、誤った取り消し、期限切れの案を勧めた数、未確定を確定と扱った数、聞いた問いの数とその中で決め方が変わった割合、検証器が見つけた条件の破り、判断できなかった時に正直に示したか。
- 各場面3〜5回。モデル・日時・プロンプトの版・回数・費用を記録する。比較相手が勝った場面も書く。

### 7.3 作り手の家での確かめ

- 直近1か月の実際のおたよりの振り返りと、期間中に届く物での実際の使用を、分けて書く。
- 測ること：おたよりが届いてから次の一手が決まるまでの時間、答えた問いの数、直した誤りの数、相手に渡せた事、自分が追いかけた回数。
- 振り返りを「使い続けた結果」とは言わない。

## 10. Claude の使い方

製品の中：

- おたより（文字・写真・PDF）を読み、文ごとの出典と条件の付いた事実にする。構造化出力で型を固定し、日付と曜日はコードが確かめる。
- 変更の連絡が、前のどの事実を変えたか、どの条件が決まったかを読む。
- 書かれていない準備（お弁当なら前日の買い物）を、「推定」として出す。家族が確かめるまで、必須として扱わない。
- 家族の一言（「来週は休みにくい」）を、答え・条件・好みに直す。足りない時は問いにする。
- 計算の結果から、理由と代償を短く説明する（画面の言葉で）。会話から計算を呼び、もしもの問いに答える。
- 品物を扱っていそうな店の種類を推定する（店・営業時間・道のりは、地図のデータで確かめる）。
- 頼み事と取り消しの文を、相手の言葉で下書きする（送るのは家族）。

開発（Claude Code を中心に置く）：

- 比べる相手の実行と、場面・正解の作成は、製品のプロンプトを直す担当から分ける（評価の独立）。
- フック：ホームの下で、このリポジトリの外を指すパスへの操作を止める。鍵・手元だけの物・実在の家族の材料の写しのコミットを止める。計算の部分を変えたら、検証器と試験を走らせる（作り始めたら足す）。
- Skills・MCP・Managed Agents は、目的と効果が言える時だけ使う。候補：おたよりの読み取りの手順（Skill）、計画のエンジンを会話から呼ぶ口（MCP）、毎朝の見直し（Managed Agents。11/3に判断）。
- 選んだ機能と、その理由・効果・失敗は、[../dev/claude-usage.md](../dev/claude-usage.md) に残す。

## 11. 言わないこと

- 「世界初」。「確認した範囲で」と書き、先行事例を並べる。
- 「公平にした」。言えるのは、家族が選んだ分担の決まりを守ったことと、誰が追いかけ、誰が穴を埋めたかの実測までである。
- 測っていない効果（「月○時間の節約」等）、追試のない心理効果、心の健康の改善。
- 検証器が全ての誤りを防ぐこと。検証器が確かめるのは、モデルに入れた条件だけである。読み取りの漏れは、出典の表示と家族の確認で減らす。
- 振り返りや模擬を、実際に使い続けた結果と言うこと。
