# 家の人の作業を含む読み取り：開発用の確認

| 03 | 振替の条件に欠席と期限内の連絡を残したが、空きのあるクラスに限る条件と、申込み後の受付確認を型化した事項・条件には残さなかった。「欠席連絡」と「振替」はいずれも `deadline` と読まれ、この応答を架空の demo に正式な事象として加えた 11/29 19:05 の計画では、その通知に由来する要件・作業・問い・「きょう」の札がなかった。 |

これは各場面一回の開発用確認である。v2 と同条件で比較していないので、上の誤りが v3 による新たな後退かは分からない。読み取りから画面・通知までの通し、写真、実家庭、一般的な正確さは測っていない。04 の対象が我が家かの判断も別に確かめる必要がある。モデルが `familyAction` を正しく付けても、下流がその事項を表示・追跡できることの証明にはならない。

実行前後の提示文・変換器のハッシュは同じだった。`extract.v3.md` の SHA-256 は `05212f1493d9338bbd24304b32cd1e3052995a43d6d858ec8ad37dc787580494`。04 の source・context・学年度を固定順でまとめた入力の SHA-256 は `5fbd6ce03c70de82dc495eb1c59706d080b33623752eecb036fd4925d7e0c93e`。応答と使用量の台帳は Git の対象外の `eval/runs/` に置いた。変更後は同じ成績を引き継がず、別の試行として記録する。
