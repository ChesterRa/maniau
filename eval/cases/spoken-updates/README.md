# 家族の一言による変更：開発用場面

架空の家庭で、音声入力などから得た**文字**を、質問への回答または変更の提案に結び付ける場面。音声認識、実際の家庭の入力、実機の評価ではない。いずれも開発用で、提出まで見せない場面はここに含めない。

## 入力と採点

- モデルには `timeZone` と `input` だけを渡し、`expected`、正解例、採点項目を渡さない。`input.state` はその場面で使える情報の要約で、実際のイベント列や画面の API 応答そのものではない。実行する製品の入力に合わせる時は、情報を増減させず、変換と不足を記録する。
- `expected.classification` は**意味の正解**で、製品の応答スキーマを指定するものではない。`referenceCommands` は現行の `Command` で表せる場合の対象と作用の略記で、JSON の形や文章を固定しない。新しい依頼の `requestId` は、確認時にアプリ側が発行する。入力にない候補を想像で追加しない。
- 変更は、対象・日付・内容を見せる提案と、家族の確認後の実行を分ける。質問や曖昧な発言では、提案しただけで事実を書き換えない。引き受けの操作は担当本人の権限を守る。
- 各 `checks` を「満たす／満たさない／判定できない」で記録し、重要項目の失敗と判定不能を別に数える。曖昧な出力を正解に寄せて解釈しない。画面で確認前に書き込まれたかは、提案文の採点とは別に操作と記録で確かめる。
- `afterPreview` は、提案を表示した後・確認前に別の操作が入る追加場面。提案時の採点とは分け、古い確認が新しい事実を黙って上書きしないかを確かめる。
- 現行の製品に入力口や命令がない場合は、その部分を「未実施」と記録し、モデルの成功にも失敗にも数えない。将来その操作が実装されたら、一日だけの変更と繰り返しの決まりを区別して再評価する。

## 場面

| 場面 | 見ること |
|---|---|
| `01-own-task.json` | 本人が引き受けた一回の作業を、できなくなった時 |
| `02-helper-reply.json` | 複数の依頼から日付で対象を選び、断られた返事を記録する時 |
| `03-read-question.json` | 持ち物を聞かれた時、条件の未定を保ち、計画を書き換えない |
| `04-ambiguous-reply.json` | 同じ相手への複数の依頼から対象を決められず、尋ねる時 |
| `05-other-adult.json` | 別の大人の引き受けを、発言者本人の権限で勝手に変えない |
| `06-one-day-routine.json` | 一日の迎えの変更を、毎週の決まりの変更と混同しない |
| `07-record-sent.json` | 本人が外へ送ったと伝えた時、対象が決まれば余計に聞かず記録を提案する |
| `08-reply-yes.json` | 日付を特定できる引き受けの返事を、別の日と混同せずに提案する |

場面の形と参照先は `node --test eval/test/spoken-update-cases.test.mjs` で確認する。通過は、モデルの理解・音声認識・実機の操作が正しいことを示さない。

## 実行器

初めは架空の場面を指定し、通信と鍵の読み込みをしない準備確認を行う。`kind` や依頼の `what` など、元の場面にない欄は空にし、欠けた情報を記録する。入力にないことを正解から補わない。事項の根拠の確かさや出典の題名など、製品の読み取り入力にない情報も記録する。不要になった依頼でも、取り消しを伝える有効な作業があれば `needed: false` を付けて残す。一日だけの作息変更は製品の命令がないため、API を呼ばず未実施とする。

```sh
node --test eval/test/*.test.mjs
pnpm --filter @maniau/server exec tsx --test ../../eval/test/utterance-product.test.ts
node eval/run-utterance.mjs --case eval/cases/spoken-updates/01-own-task.json
```

製品の一言の読み取りが利用できる時、架空の材料だけで実際に呼ぶには次のようにする。`.env` の鍵を使う。読み取り・変換とも製品の関数を呼び、モデル・プロンプト・出力上限はその時の製品の設定に従う。

```sh
pnpm --filter @maniau/server exec tsx ../../eval/run-utterance.mjs --case eval/cases/spoken-updates/01-own-task.json --execute
```

単価を記録する場合は、実行時に公式料金を確認し、`--pricing-model`、`--input-usd-per-million`、`--output-usd-per-million`、`--pricing-url`、`--pricing-checked` をすべて付ける。モデルが一致せず、推論地域が global・速度が standard と確認できず、またはキャッシュ料金がある場合、費用は不明とする。読み取り開始と応答・使用量を一件ずつ台帳に残す。応答を得られない時の費用は 0 とせず不明にする。自動再試行はしない。

読み取り、検査、プロンプト、依存の固定のハッシュを試行前後に記録する。試行中に変わった場合は、その結果を比較不能とする。記録したハッシュはファイル全体の再現可能性を高めるものであり、実行環境のすべてを固定した証拠ではない。

分類と参照命令の照合は補助的な診断であり、各確認点の合否ではない。画面の文や、確認前・確認後の実際の書き込みはこの実行器からは分からないため、各 `checks` と `afterPreview` は未判定または未実施のまま残す。画面と操作ができた後、別に確かめて採点する。

開発用の記録は Git 対象外の `eval/runs/` に置く。保留場面を実行した場合は、入力と生の出力を開発用の記録に混ぜず、保留場面のディレクトリ内に置く。保留場面は製品の調整担当に見せない。

## 実際の計画から作る持ち物の前提

`eval/belongings-utterance.ts` は、架空のデモの事象から製品の計画と一言の前提を作る。静的な場面だけでは確かめられない「家にあるか」の値を含む。有る・無い・有ると答えた後の訂正、以前からある外部の返事と質問、店種の分からない物、同名で要る日が異なる物の七場面である。追加のお知らせの読み取りは固定の架空応答を使い、正解は一言の読み取りに渡さない。

```sh
pnpm --filter @maniau/server exec tsx --test ../../eval/test/belongings-utterance.test.ts
pnpm --filter @maniau/server exec tsx ../../eval/run-belongings-utterance.ts
```

二つ目のコマンドも初期状態では偽物を使う形の確認で、モデルの正しさを示さない。架空の材料で実際に読む時だけ `--execute` を付ける。`--case home-yes` のように一場面だけも選べる。料金は上の実行器と同じく `--pricing-model`、`--input-usd-per-million`、`--output-usd-per-million`、`--pricing-url`、`--pricing-checked` を全て指定した時だけ見積もる。指定しない時や料金条件を確かめられない時は不明とする。

各試行では候補の種類と対象、確認前に事象を書かなかったか、確認後の命令と状態を別々に記録する。質問の対象は必要な事項が含まれるかだけを照合し、余分な事項や説明文の正しさは判定しない。画面の説明と実機は未判定のままであり、この実行器の一致を画面の合格とはしない。実行前後に前提を作るコードと架空資料のハッシュを照らす。生の応答と通信・費用の台帳は `eval/runs/` に置き、Git に入れない。
